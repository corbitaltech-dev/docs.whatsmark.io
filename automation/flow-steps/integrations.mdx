The **Integrations** category flow steps lets your chatbot work with Google services. Automatically save customer information to Google Sheets or create Google Calendar events. These steps run in the background and don't send any message to the customer.

<Note>
Both steps need a connected Google account. Set one up first in [Google Accounts](/settings/google-accounts).
</Note>

## Google Sheets

**What it does.** Adds a new row to a Google Sheet each time the flow reaches this step.

**When to use it.** Use it to automatically save **leads**, **bookings**, **orders**, **survey responses**, or any other customer information in Google Sheets.

**How to set it up.**

<Steps>
<Step title="Choose the Google Account (required)">
  Pick a connected account, or click **Connect another account** to add one.
</Step>

<Step title="Pick the Spreadsheet (required)">
  Your spreadsheets load automatically. Choose the one you want to write into, or type a name in the box below the list and click **Create** to make a new one on the spot.
</Step>

<Step title="Set the Sheet / Tab Name">
  Optional. The tab within that spreadsheet — leave it as `Sheet1` unless you keep your data on a differently named tab.
</Step>

<Step title="Map your Column Values (required)">
  Click **Add Column** for each one. Give it a header, then set the value — type **@** to insert a [merge field](/messaging/merge-fields) such as the contact's name or an answer you collected earlier. Add at least one column, or the step has nothing to write.
</Step>
</Steps>

![Google Sheets settings with a Google Account field required and highlighted in red, a Sheet / Tab Name field set to Sheet1, and a Column Values section prompting you to add at least one column](/automation/img/integrations/google-sheets-settings.png)

**Example**

A restaurant logs every booking taken by the chatbot:

| Column header | Value |
| --- | --- |
| Name | {'{{contact.first_name}}'} {'{{contact.last_name}}'} |
| Phone | {'{{contact.phone}}'} |
| Date | {'{{vars.booking_date}}'} |
| Party size | {'{{vars.party_size}}'} |

<Tip>
Put this step at the very end of your flow, after every question has been answered. If you place it earlier, the later answers won't exist yet and those cells will be blank.
</Tip>

## Calendar Event

**What it does.** Creates an event in your Google Calendar using details the customer gave you.

**When to use it.** Appointments, site visits, consultations, demos — anything where a booking on WhatsApp should also appear in your calendar.

**How to set it up.**

<Steps>
<Step title="Choose the Google Account (required)">
  Pick the connected account, or click **Connect another account** to add one.
</Step>

<Step title="Choose the Calendar">
  Optional. Pick which of that account's calendars the event should go into, or create a new one by name. Leave it blank and the event goes to your primary calendar.
</Step>

<Step title="Write the Event Title (required)">
  For example, `Appointment with {'{{contact.first_name}}'}`.
</Step>

<Step title="Set the Start Date (required)">
  Type a date in any common format — `2026-06-04`, `04/06/2026`, `June 4` — or press **@** to use an answer the customer gave earlier. It's converted into a proper date for you.
</Step>

<Step title="Add the optional details">
  **Start Time**, **End Date**, **End Time**, **Location**, **Attendee Email** and **Description** are all optional, and **@** works in any of them. Leave **End Time** blank and the event runs for an hour from the start. Fill in **Attendee Email** and the customer is sent a calendar invite.
</Step>
</Steps>

<Columns cols={2}>
  ![Calendar Event settings with Google Account, Event Title, and Start Date fields all required and highlighted in red, and a tip explaining that typing @ inserts a merge field or an earlier Ask Question reply](/automation/img/integrations/calendar-event-settings.png)

  ![Calendar Event settings continued, showing the optional Start Time, End Date, End Time, Location, Attendee Email, and Description fields](/automation/img/integrations/calendar-event-settings-optional.png)
</Columns>

**Example**

A clinic turns a WhatsApp booking into a calendar entry:

> **Title:** Consultation — {'{{contact.first_name}}'} {'{{contact.last_name}}'}
> **Start Date:** {'{{vars.booking_date}}'}
> **Start Time:** {'{{vars.booking_time}}'}
> **Location:** Green Valley Clinic, Room 3
> **Attendee Email:** {'{{contact.email}}'}
> **Description:** Booked through WhatsApp. Phone: {'{{contact.phone}}'}

The doctor sees it in their calendar, and because **Attendee Email** was filled in, the patient gets a Google invite by email too.

## WooCommerce Condition

**What it does.** Checks one field of the WooCommerce order that started the flow, then sends the flow down a **yes** or **no** path.

**When to use it.** Use it after an [**Order node**](/automation/flow-builder#woocommerce) trigger to run the flow only for specific orders, such as **shipped orders, cash-on-delivery orders, or high-value orders.**

**How to set it up.** Pick a field, pick an operator, and type the value to compare against.

The fields you can check:

| Field | What it holds |
| --- | --- |
| **WooCommerce order status** | The order's status now, such as `completed` |
| **Previous order status** | What it was before this change |
| **Order total** | The order value |
| **Currency** | The order's currency |
| **Payment method** | How they paid |
| **Is cash on delivery** | `1` for yes, `0` for no |
| **Tracking number** | The shipment tracking number, if your store sets one |
| **Item count** | How many items were bought |

The operators: **Equals**, **Does not equal**, **Contains**, **Starts with**, **Ends with**, **Is empty**, **Is not empty**, **Greater than**, **Less than**, **Greater than or equal**, **Less than or equal**.

Connect the green **yes** handle on the top right and the red **no** handle on the bottom right to what should happen next.

![WooCommerce Condition settings with an Order field set to WooCommerce order status, an Operator set to Equals, a Value of Completed, a warning that it only works in flows triggered by WooCommerce, and a note that the green top-right handle is the YES branch and the red bottom-right handle is the NO branch](/automation/img/integrations/woo-condition.png)

**Example**

> **Order field:** WooCommerce order status
> **Operator:** Equals
> **Value:** Completed

<Note>
This step only works in a flow whose **Start Trigger** is a WooCommerce event. In any other flow it always takes the **no** path.

On **abandoned cart** events, most order fields are empty — only **Order total** and **Item count** have values, so check one of those.
</Note>

## A worked example

A consultancy books discovery calls end to end:

1. **Start Trigger** — When message contains `book`, `call`, `consultation`.
2. **Ask Question** (Text) — "What's your full name?" → `client_name`
3. **Ask Email** — "What's your email?" → `email`
4. **Ask Question** (Date) — "Which day suits you?" → `booking_date`
5. **Ask Question** (Text) — "And what time?" → `booking_time`
6. **Update Contact** — save the name and email onto the contact record.
7. **Calendar Event** — create the event from those answers.
8. **Google Sheets** — log the same details as a row for the sales team.
9. **Text Message** — "You're booked in for {'{{vars.booking_date}}'} at {'{{vars.booking_time}}'}. A calendar invite is on its way to {'{{vars.email}}'}."

![The finished booking flow — a Start Trigger leading through Ask Question, Ask Email, and two more Ask Question steps, into a Google Sheets step, a Calendar Event step, and a final Text Message confirming the booking](/automation/img/integrations/worked-example-booking-flow.png)
